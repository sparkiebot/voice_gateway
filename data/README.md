# Sparkie Needle fine-tuning data

`sparkie-tools.jsonl` is generated by `bin/build-finetune-dataset` from the
reviewed utterances in `responses.it.json` plus manually curated robot-state,
navigation, volume, environment, follow, and off-topic examples. Regenerate it after changing the tool
catalogue or local phrases:

```bash
bin/build-finetune-dataset
```

The current set intentionally includes:

- every local phrase with ordinary and punctuated forms;
- representative utterances for every non-local tool in `tools.json`;
- four navigation forms for each reviewed location;
- unrelated and unsupported requests mapped to `answers: []` (45 of 313, about 1/8).

Do not add an example unless its expected call and every argument are grounded
in the query. Test candidate data against a held-out evaluation set rather than
training and evaluating on the same phrasings.

With this few-hundred-example set, use 10–30 epochs rather than Needle's
three-epoch default, and inspect validation loss after every epoch.

Before training an augmented file, canonicalize it against the currently
deployed tool catalogue:

```bash
bin/validate-finetune-dataset data/sparkie-tools.gemini.raw.jsonl data/sparkie-tools.jsonl \
  --output data/sparkie-tools.gemini.jsonl
```

The validator pins the current tool schemas and Italian system facts, requires
one-or-zero calls, validates arguments, rejects local phrases the gateway would
not answer, and removes case-insensitive duplicates.
